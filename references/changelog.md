# 版本变更记录

## v4.0.0 — 2026-10-28（双渠道任务 + 接口核验，修掉「说完成了其实没完成」）

**现象**：用户在库库AI里跑完 Skill，Agent 汇报「已发 3 条、知识广场已停留」，
打开 PC 客户端任务中心却是 `与库库聊聊热门话题(0/3)`、每张卡还是「去完成」。

**根因（实测确认）**：每日任务进度按渠道独立统计，两套 `task_from`：

| 渠道 | task_from | 任务数 | 备注 |
| --- | --- | --- | --- |
| 网页端 | `kuku_signin_30_web` | 6 | 有「下载并登录库库PC客户端」 |
| PC 客户端 | `kuku_signin_30_pc` | 7 | 多「导入网盘文件」「上传本地文件」，无「下载客户端」 |

v3 只做了网页端，所以客户端里永远是 0。签到是账号级，不受影响。

**改动**：

| 位置 | 改动 |
| --- | --- |
| `scripts/kukuai_checkin.py` | 重写任务层：先拉 `tasklist` 算真实剩余 → 做真实动作 → `taskcomplete` 上报 → 再拉 `tasklist` 核验 |
| 同上 | 聊天改为「一条消息一个新会话」，并取 URL 里的 `session_id`；不带 `session_id` 会 `errno=194001` |
| 同上 | 上报必须带 `window.jsToken`，否则 `errno=8002` |
| 同上 | 签到改为直连活动页点 `button.pc-sign-btn`，不再依赖首页签到卡/iframe（卡片有时不渲染） |
| 同上 | 新增上传占位文件（`UPLOAD_LOCAL_FILE`）、导入网盘文件（需授权）、专家任务（首次需勾协议） |
| 同上 | 新增 `--channels web|pc`、`--no-upload`、`--with-netdisk`、`--deadline` 硬超时 |
| 输出 | 新增 `task_board` / `channels`（两端完成度），摘要里明确写「没做的任务及原因」 |
| SKILL.md | 顶部加「汇报纪律：只认接口核验」，新增错误码表与双渠道说明 |

**验收**：同一账号同一天实测，网页端 chat 3/3、square 1/1、expert 1/1；PC 客户端 chat 3/3、square 1/1、expert 1/1、upload 1/1，全部由 `tasklist` 复核确认。

## v3.7.1 — 2026-10-28（文档引导强化：别的 Agent 不再跳过工具）

现象：把 zip 丢给其他 Agent，它读完说明直接让用户「按 F12 复制 BDUSS/STOKEN」，
完全没提自带的 `tools/GetCookie.exe`；用户回「我不会，有没有工具」才暴露问题。

改动：

| 位置 | 改动 |
| --- | --- |
| SKILL.md 正文最顶部 | 新增「⛔ 第一步：先启动 Cookie 工具（不可跳过）」，含能执行命令 / 不能执行 GUI / 用户说不会 三种情况的具体说法 |
| SKILL.md frontmatter | `description` 里写明「自带 tools/GetCookie.exe，不要让用户按 F12」 |
| 压缩包根目录 | 新增 `START-HERE.txt`，给 AI 和用户各一段说明 |
| `安装说明.txt` | 开头加「★ 请先看 START-HERE.txt ★」 |
| Cookie 章节 | 标题改为「默认用自带工具；手动方式仅作兜底」，B/C 明确标注兜底 |

强调查明的事实：手动 F12 复制经常漏 `STOKEN`，而缺 `STOKEN` 必然 `errno=-6`，等于白折腾。

## v3.7.0 — 2026-10-27（只存 2 条 Cookie + 启动/关闭提速）

**Cookie 精简**：逐组删减实测，只需要两条，其余 20 多条都是登录过程的副产物：

| 保留 | 作用 | 缺失后果 |
| --- | --- | --- |
| `BDUSS`@`.baidu.com` | 账号身份 | `errno=-6` |
| `STOKEN`@`.kuku.baidu.com` | 活动域会话令牌 | `errno=-6` |

- 27 条 → 2 条，复制内容从约 4.3 KB 降到 430 字符
- 必需项不全时**原样保留全部**，不会存出一个不能用的文件

**性能**：

| 问题 | 原因 | 修法 |
| --- | --- | --- |
| 打开时左上角闪一下 | 窗口先以默认位置显示，`geometry` 后才居中 | `withdraw()` → 布局算完 → `deiconify()` |
| 打开卡一下 | 初始化时 `free_port()` 逐端口 connect 探测，超时累积 | 改成 bind 试探（毫秒级），且推迟到点 ① 时才挑端口 |
| 关闭卡一下 | 关窗时在主线程杀进程 + `sleep(1)` + 删临时目录 | 立刻销毁窗口，清理丢后台线程（实测 1.5s → 0.15s） |

**清理**：删掉邀请页副标签相关代码（`INVITE_URL` / `browser_ws` / `open_tab`）。

## v3.5.0 — 2026-10-27（登录页改到活动所在域 kuku.baidu.com/app）

第三组样本（含 `passport.kukuai.cn` 的 PTOKEN/SAVEUSERID/STOKEN）终于登进工作台了：
`www.kukuai.cn` 的 `userreport` 返回 `errno:0`，积分能读到 2000。**但签到卡还是「登录领奖」**。

继续查发现：

| 事实 | 结论 |
| --- | --- |
| `www.kukuai.cn` 接口 errno=0，`kuku.baidu.com` 接口 errno=-6 | 两个入口是**两套独立会话** |
| 签到活动 iframe 在 `kuku.baidu.com/operation/activitys/kukuPcSignAct/main` | 签到只认 `kuku.baidu.com` 的登录态 |
| 把 BDUSS 复制到 `.kuku.baidu.com` | 活动页跳 `wappass.baidu.com` 登录并 `ERR_TOO_MANY_REDIRECTS`，整页报错 |

所以：**登录页改成 `https://kuku.baidu.com/app`**，服务端复核也换成该域的 `userreport`；
并明确警告不要把 BDUSS 往 `.kuku.baidu.com` 复制。

## v3.4.0 — 2026-10-27（加服务端复核：接口说未登录就不算成功）

第二组真实样本暴露的问题：BDUSS 明明在 `.kukuai.cn` 域、在百度首页也能认出账号（`176****54`），
但工作台接口 `userreport` 仍返回 `errno:-6 未登录`，页面签到卡也还是「登录领奖」。

| 变化 | 说明 |
| --- | --- |
| 服务端复核 | 发现 `.kukuai.cn` 的 BDUSS 后，用页面上下文 `fetch` 调 `userreport`，**`errno=0` 才算成功** |
| 复核不通过 | 连续 8 次仍未登录 → 红条提示「登录可能没真正完成，确认右上角出现头像后点 ① 重试」，**不再误报成功** |
| 读取范围 | `COOKIE_HOSTS` 增加 `passport.kukuai.cn`、`passport.baidu.com`，避免漏掉登录配套 cookie |

排查记录：试过把 BDUSS 复制到 `.www.kukuai.cn`、统一 BAIDUID、原样四种组合，接口一律 `errno:-6`，
说明这份会话确实不被工作台接受（不是浏览器注入方式的问题）。同时今早那份能用的 Cookie 现在也失效，
怀疑平台今天改了会话机制或账号被要求重新验证。

## v3.3.0 — 2026-10-27（登录判定按域，修复「抓了个没用的 Cookie 却说成功」）

真实样本复盘：用户在一组 Cookie 上遇到「exe 说抓取成功，但签到脚本报未登录」。查清了：

| 问题 | 真相 | 修复 |
| --- | --- | --- |
| 抓到了 `.baidu.com` 的 BDUSS 就报成功 | 工作台用 `passport.kukuai.cn` 自己的会话，只认 `.kukuai.cn` 域的 BDUSS | 判定改为「BDUSS 必须挂在 kukuai.cn 域」，否则不算成功 |
| 登录页是 `kuku.baidu.com/home`（下载落地页） | 在那页登录只写 `.baidu.com`，工作台不认 | 登录页改成工作台 `https://www.kukuai.cn/`，邀请链接作副标签打开 |
| 用户找不到登录入口 | 入口是工作台**左下角签到卡上的「登录领奖」** | 窗口黄色提示框、等待状态、日志三处都写明这个位置 |
| 只有百度域 BDUSS 时会傻等到超时 | 缺提示 | 检测到这种情况立刻提示「还差一步：点左下角登录领奖」 |

> 顺带修一个自己引入的 bug：改常量时把 `COOKIE_HOSTS` 删了，导致读 cookie 直接抛异常、永远判不出登录。

## v3.2.0 — 2026-10-27（Cookie 工具改成图形界面）

`tools/GetCookie.exe` 从「双击就弹浏览器」改成两按钮窗口：

| 变化 | 说明 |
| --- | --- |
| 不再自动开网页 | 打开只显示窗口，等用户点按钮 |
| 按钮 ① | 打开默认浏览器的独立窗口 → 登录页 → 自动抓取并保存，状态条变绿「抓取成功，已保存 N 条」；失败变红说明原因 |
| 按钮 ② | 把已抓到的 Cookie 复制到剪贴板，状态条提示去 Agent 对话粘贴 |
| 登录页 | 改成 `https://kuku.baidu.com/home?invite_code=...`：实测 360 浏览器加载 `www.kukuai.cn` 会在 8 秒左右进程退出，调试端口断掉抓不到 Cookie |
| 依赖 | WebSocket 客户端改为标准库自实现，**零第三方依赖**；exe 改无控制台窗口（windowed） |
| 其它 | 同一 cookie 去重；重新抓取失败时保留上次结果，② 仍可复制 |

命令行模式保留：`GetCookie.exe --cli --no-browser --port N` 供自动化复用。

## v3.0.0 — 2026-10-27（把云端调试踩的坑全部修进主流程）

这版只在原来的「签到 + 任务」脚本上加固，功能没变。

| 问题 | 表现 | 修法 |
| --- | --- | --- |
| 点签到卡标题会跳空页 | 落到 `#/workbench/new-task`，那里没有签到卡 | 改 DOM 点击；每个入口点完验证 iframe，没出现就回首页换下一个，最多两轮 |
| 关弹窗把任务中心一起关了 | 刚打开就消失，读不到按钮 | `ensure_task_center()` 打开成功后不再调 `dismiss_blockers()` |
| iframe 里按钮渲染慢 | 读不到 `button.pc-sign-btn`，误判「页面改版」 | 轮询最多 16 秒等按钮或已签标记 |
| 已签时还去点按钮 | 日志写成 `signin_clicked`，语义误导 | 按钮文案含「已签/明天再来」直接判已签并跳过 |
| 偶发打开超时/白屏 | `goto Timeout 30s`、主区域空白 | `goto_home()` 重试 3 次 + 超时 60 秒；`wait_ready()` 检测渲染，最多重载 3 次 |

本地实测：签到 `已签`、积分 2000、热门话题 3/3、知识广场 已完成、专家项默认跳过。

## v2.1.0 — 2026-10-27（真实账号跑通后修正）

用真实 Cookie 在本人账号上完整跑通后修掉的问题：

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 已登录却报「登录态失效」 | 已登录时签到卡 CTA 是「去抽会员」，被当成未登录信号 | 只有 CTA 含「登录」才判负；有 CTA 且不含「登录」直接判已登录 |
| 任务只发出 1 条对话 | 每条消息都重开任务中心，第二次就找不到输入框 | 点一次「去完成」后连发；并按标题里的 `(1/3)` 只补剩余次数 |
| 收尾误报「未确认签到成功」 | 页面跳到对话页后读不到按钮，`False` 覆盖了早先的 `True` | 只要任一阶段读到已签就视为已签 |
| 专家任务一直 skipped | 点「召唤」会弹用户协议，没勾选就没有输入框 | 自动勾「我已阅读并同意」→「继续使用」，并写进 notes |
| 读完任务却认不出已完成 | 只认 `btn_todo`/`btn_invite` | 补 `btn_done` = 已完成，直接跳过 |
| 任务清单多一项 | 「下载并登录库库PC客户端」该账号不展示 | 从配置移除，改在 notes 说明「部分账号才有」 |

实测结果：签到「今日已签」，热门话题 3/3、专家对话、知识广场三项全部 `btn_done`，积分 2000；再跑一次全部返回「今日已完成」，幂等。


## v2.0.0 — 2026-10-27（适配 2026-10-21 起新一期活动）

旧版（v1.x）写死的是 9 月那期「送你一台云电脑，每日签到领网盘会员」（2026-09-29 ~ 10-31），那套入口与按钮在 10-21 新期上线后已失效。

### 活动本身变了

| 项 | v1（9 月期） | v2（10 月期 / 当前） |
| --- | --- | --- |
| 活动名 | 送你一台云电脑，每日签到领网盘会员 | 每日签到得网盘SVIP月卡 · 做任务抽好礼 赢苹果笔记本 |
| 周期 | 2026-09-29 ~ 10-31 | 2026-10-21 ~ 12-04 |
| 节点 | 3 / 5 / 7 天，满 7 天开新一轮 | 3 / 7 / 15 / 30 天，30 天必得月卡 |
| 每日签到 | 50 积分 + 1 次抽奖 | 积分 + 抽奖（数额以页面为准） |
| 任务 | 每日登录、完成一次对话 | 6 项清单：热门话题×3、召唤专家、知识广场10s、下载登录PC端、2 条邀请 |

### 页面结构变了

| 项 | v1 | v2 |
| --- | --- | --- |
| 签到入口 | 右上角头像菜单 → 「免费领积分」面板 | 工作台**左下角签到卡** `[data-testid="signin-promo"]` |
| 签到按钮 | 「领取50」 | `[data-testid="signin-promo-cta"]`（未登录「登录领奖」，签到后变已签文案） |
| 完成态 | 按钮变「明日再来」 | CTA 文案变化 + 标题/日格状态 |
| 活动页 | 无独立页 | `button.activity-banner` → 活动弹窗（规则 / 奖品 / 去抽奖 / 任务清单） |
| 页面锚点 | `[data-testid="user-profile-trigger"]` | 签到卡 `data-testid` 系列 + 活动弹窗 `[class*="activity-dialog"]` |

### v2 开发期用真实浏览器校准到的事实

- **登录误判**：未登录时 `[data-testid="user-profile-trigger"]` 也存在，v1 的判定逻辑会误判。v2 改用负向标记「登录领网盘会员」「登录领取网盘SVIP」「登录后领取连签奖励」+ CTA「登录领奖」。
- **每日奖励是「积分+10、抽奖+1」**，不是旧期的 50；`assets/activity.json` 已按实测值修正。
- **活动内容在 iframe 里**：`iframe.signin-center-iframe` → `kuku.baidu.com/operation/activitys/kukuPcSignAct/main`。该地址单独打开 body 为空，必须从工作台点签到卡标题打开弹窗。
- **「去完成」是图片按钮**（`btn_todo.png`），DOM 里没有文字节点；必须 `.pc-kuku-task-card` → 读图名 → 点 `.pc-kuku-task-card__action`。
- **会员弹窗遮罩**会拦掉真实点击（`locator resolved ... but click timed out`）：首页加载弹一次、打开任务中心又弹一次，需先点 `activity-dialog-close`，仍失败退化为 DOM 级 `element.click()`。
- **任务清单只有 6 项**，没有第三方攻略写的「上传本地文件」「导入网盘文件」。
- **积分误匹配**：页面文本「10.28 积分+10」会被通用正则解析成 28 分，已加 `(?<![\d.])` 与 `(?!\s*\+)` 约束。
- **连签天数误匹配**：「连签3天」是节点标签，不能当连签天数，只认「已连签/已签N天」。
- **SPA 无链接可扫**：页面只有一个备案 `<a href>`，只能靠选择器/文案点击。

### 脚本能力变了

- 入口解析三级兜底：点签到卡标题开任务中心 → 点活动横幅 → 点入口文案（都走选择器，SPA 没有可扫的链接）。
- 新增状态解析：连签天数、下一节点还差几天、活动倒计时、任务进度 `(n/m)`、积分、抽奖次数。
- 新增任务自动化：话题对话×3、专家对话、知识广场停留 12s、生成占位文件上传；网盘导入需显式开关。
- 新增连签状态持久化 `~/.kukuai/state.json`：断签预警、节点达成提醒、活动临期提醒。
- 新增 `kukuai-summary-*.md` 汇总，可直接推送给用户。
- 新增 `assets/activity.json`：活动周期、节点、入口/签到文案、任务清单全部配置化，**换期只改这一个文件**，脚本不用动。

## 后续换期怎么做

1. 打开库库AI 活动页，抄下：活动起止日期、连签节点、每日签到奖励。

3. 若按钮文案变了（例如不再是「立即签到」「去完成」「去领取」），同步改 `entry_texts` / `signin_texts` / `tasks[].actions`。
4. 跑 `--dry-run --probe-entry` 验证能进活动页并正确读出连签天数，再正式执行。
